# 角色开发与云端接入

## 现在怎么创建角色

1. 复制 `examples/character_template.json`，修改 `id`、名字、属性、普攻和技能。
2. 将立绘、小人图片放在 JSON 旁边，在 `assets.portrait`、`assets.sprite` 中填写文件名。技能图标填在各技能的 `icon` 中。图片均可省略；省略时显示占位图，角色仍能战斗。
3. 编译并启动游戏。在干员选择页，将 JSON 文件拖入游戏窗口。资源会复制到**游戏可执行文件旁的 `characters/`**，保存成功后角色立即进入选择列表。
4. 用左右键选择角色，Enter 确认，再选择关卡出战。角色超过三名会自动翻页。以后启动游戏会自动加载已保存角色；手动编辑保存文件后，在菜单按 F5 刷新。

导入文件中的图片路径相对于**该 JSON 文件所在目录**。支持 PNG、JPG/JPEG、BMP；单图不超过 32 MiB、边长不超过 8192，图片必须可以解码。角色 JSON 不超过 1 MiB。推荐透明 PNG；单张小人图片无需填写图集参数。

同一个 `id` 再次导入会更新该角色。导入先复制新资源，再提交 JSON；导入失败会保留旧配置和旧资源。旧版本图片暂不自动清理，以免破坏已保存引用。角色库需要目录写入权限；放在不可写目录时会明确提示失败。

也可使用命令行（以下为项目根目录中的 PowerShell 命令）：

```powershell
.\cmake-build-debug\character_tool.exe validate .\examples\character_template.json
.\cmake-build-debug\character_tool.exe import .\examples\character_template.json
# 可选第三个参数：指定另一角色库目录。
# 游戏默认只读取可执行文件旁的 characters/，不会自动发现其他目录。
```

`validate` 检查配置内容；`import` 另外检查、解码和复制图片。导入后重新启动游戏，或在菜单按 F5。

`assets/characters/demo_guard.json` 是完整的“示例剑士”：复用项目现有图片，演示近战、剑雨、治疗与增益。内置样例先加载，本地角色库后加载；相同 id 的本地配置覆盖样例。构建只复制 `assets/`，不会覆盖导入的 `characters/`。

## 配置格式

```json
{
  "schemaVersion": 1,
  "id": "my_guard",
  "name": "新角色",
  "description": "角色介绍",
  "assets": { "portrait": "portrait.png", "sprite": "sprite.png" },
  "stats": { "health": 5, "moveSpeed": 320, "jumpSpeed": 610, "jumps": 2, "attackInterval": 0.25 },
  "attack": { "type": "melee", "amount": 2, "range": 120, "lifetime": 0.15 },
  "skills": [
    {
      "name": "治疗强化",
      "description": "恢复两点生命，四秒内普攻伤害提升",
      "cooldown": 10,
      "duration": 4,
      "effects": [
        { "type": "heal", "amount": 2 },
        { "type": "buff", "damageMultiplier": 1.8 }
      ]
    }
  ]
}
```

只必填 `id` 和 `name`；其余使用默认值。`id` 是稳定的保存键：1–64 个小写英文字母、数字、下划线或短横线。改变 id 会创建另一名角色。未知字段、未知效果、非法数值或不支持的版本会报错，避免拼错字段后静默使用默认值。

### 图片与动画

`assets` 支持：

| 字段 | 默认值 | 意义 |
| --- | --- | --- |
| portrait / sprite | 空 | 立绘 / 小人本地图片引用 |
| columns / rows | 1 / 1 | 等尺寸网格图集的列数、行数，各 1–64 |
| idleRow | 0 | 待机行，从 0 开始 |
| runRow / attackRow / jumpRow / fallRow / dodgeRow / hurtRow / defeatedRow | -1 | 动作行；-1 使用默认程序动作 |
| fps | 8 | 每秒播放帧数，0.1–60 |
| height | 112 | 游戏内绘制高度，24–300 |

每行默认使用全部列，也可用 `rowFrameCounts` 设置各行有效帧范围；加载时自动跳过完全透明的格子。向左时水平翻转；单张图片就是 1×1 图集。图片尺寸必须能被网格整除。单图默认带基础程序动作，也支持上传分件后自动围绕关节运动，详见[默认动作与分件规范](默认动作与分件规范.md)。倒地帧播放一次后停止。暂不支持蒙皮或角色专属 VFX 上传配置。

### 技能效果

`skills` 最多两项，按顺序绑定 E、Q；可只填一个或完全省略。每个技能需要 `name` 和 1–8 个 `effects`。普攻 `attack` 支持 projectile、melee、rain。战斗输入与移动由 `Player` 管理，技能由 `CharacterRuntime` 执行。

| type | 执行行为 | 主要参数 |
| --- | --- | --- |
| projectile | 沿面向发射弹道 | amount、speed、count、spread、radius、lifetime |
| melee | 面向前方生成近战命中区域 | amount、range、lifetime |
| rain | 在敌人上方生成落剑 | amount、speed、count、range、radius、lifetime |
| heal | 恢复生命，最多达到角色生命上限 | amount（非负整数） |
| buff | 在技能持续期间改变普攻 | damageMultiplier、attackSpeedMultiplier |

伤害效果共有 `damageType: "physical" / "arts"`、`stun`（眩晕秒数）、`destroysProjectiles`（是否抵消敌方弹道）。伤害会继续走现有 Boss 命中与伤害流程。`spread` 是相邻弹道之间的角度，单位弧度；`range` 在 melee 中表示前方攻击长度，在 rain 中表示落剑分布宽度。`count` 为 1–32，`amount` 为 0–10000。每帧最多保留 4096 个玩家弹体，防止配置造成无界增长。

当前 Boss 沿用原有统一伤害计算，尚未按 physical/arts 区分护甲或法抗；damageType 已随弹体传递，可用于后续扩展伤害结算。

技能 `cooldown` 从施放时开始计算，至少 0.05 秒；技能仍在生效时不能重复施放。`duration` 默认 0；`interval` 默认 0，表示只在施放瞬间执行一次。设置正数 `interval` 时，非 buff 效果会在 `duration` 内重复执行，施放时也执行一次，结束时刻不再补一次。最小重复间隔为 0.05 秒。

buff 必须设置正数 duration。多个 buff 乘算，最终普攻伤害倍率上限 100，攻速倍率上限 10，普攻间隔下限 0.03 秒；buff 不增强技能自身伤害。治疗不会复活已死亡角色。新角色普攻默认不消耗弹药；已有能天使弹匣、德克萨斯模式切换和专属动画仍保留原实现。

技能名字、描述是展示文本，实际行为由 `effects` 的结构化字段决定。填写自然语言不会自动生成新机制。需要召唤、传送等新效果时，在 `EffectType`、JSON 编解码与 `CharacterRuntime::Apply` 中增加一次处理，此后所有角色均可配置使用。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| src/character.h / .cpp | Character 数据类、JSON 编解码与校验、CharacterRuntime 实例状态和效果执行 |
| src/character_repository.h / .cpp | 本地存储、资源导入、云端仓库接口与适配器 |
| src/character_art.h / .cpp | 按 id 缓存纹理、释放资源、绘制配置角色 |
| src/player.h / .cpp | 接受 Character 创建可操作角色、共享移动/碰撞、技能 HUD |
| src/main_menu.h / .cpp | 动态角色列表、翻页、选择与状态提示 |
| src/game.cpp | 加载角色库、拖拽导入、刷新、出战创建 |
| src/character_tool.cpp | 命令行校验和本地导入 |

`Character` 只保存可持久化定义。`CharacterRuntime` 持有自己的配置副本和技能计时器；多个实例不会共享冷却、生命或动画状态。数据库只保存 `Character::ToJson()`，不保存纹理句柄、指针或战斗中计时器。

## 后续接入 API / 云端数据库

目前**没有连接真实云端，也没有自动上传**。`ICharacterRepository` 定义 `LoadAll()` 和 `Save()`；`LocalCharacterRepository` 已落地，`CloudCharacterRepository` 接受你实现的三个回调：

```cpp
CharacterCloudApi api;
api.listCharacters = [&client]() -> std::vector<std::string> {
    return client.ListCharacterJson();
};
api.uploadAsset = [&client](const std::filesystem::path& path) -> std::string {
    return client.UploadImage(path); // 成功后返回 https URL
};
api.putCharacter = [&client](const std::string& id, const std::string& json) {
    client.UpsertCharacter(id, json); // 必须检查响应；失败抛异常
};
CloudCharacterRepository cloud(api, localRepository.Root());
cloud.Save(character); // 先上传本地图片，再保存包含远程 URL 的 JSON
```

以上 `client` 为接口示意，需要替换成你实际使用的 HTTP/数据库 SDK。未设置回调、资源缺失、上传未返回 https URL、后端报错都会抛异常；不会假装保存成功。`Save` 不修改原本地配置。列表中的单个坏记录会进入 `CharacterList::errors`，其他合法记录仍可使用。

建议后端以 `(ownerId, characterId)` 唯一标识文档，保存 `schemaVersion`、配置 JSON、服务端更新时间；图片放对象存储，数据库保存 URL。认证、角色归属验证、访问权限由服务端落实，密钥不放进角色 JSON。当前接口使用 upsert/最后写入覆盖；若需要多人编辑，请在 API 层添加 revision/ETag 冲突控制。

调用为同步接口，应在你未来的 API 工作线程中执行网络操作，在游戏主线程提交配置并加载纹理。云端返回的图片 URL **不会由渲染器直接下载**：接入时应下载到本地缓存，将图片引用解析成缓存路径后，调用 `CharacterArt::RegisterCharacter`，再更新菜单列表。缓存、认证、重试、离线队列和自动同步尚未实现。

若图片上传成功而文档保存失败，异常会向调用方传播，本地角色仍然可用；已上传图片的去重或孤立资源回收由后端管理。

## 验证

```powershell
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
.\cmake-build-debug\character_render_smoke.exe
```

单元测试无需图形窗口，覆盖 JSON 往返、非法配置、独立运行状态、增益/治疗/冷却/落剑/近战/持续效果边界、原子更新、资源复制、导入失败保留旧数据、云端错误传播。最后一个命令需要可用的 OpenGL 环境，使用隐藏窗口生成 `cmake-build-debug/character-qa/menu.png` 和 `battle.png`，用于人工检查图片和中文 HUD。

JSON 解析使用随仓库提供的 nlohmann/json 3.11.3，许可证见 `third_party/nlohmann/LICENSE.MIT`，不增加构建时下载依赖。
