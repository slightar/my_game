# 默认动作与分件规范

## 最简单：上传一张小人

```json
{
  "id": "new_hero",
  "name": "新角色",
  "assets": { "sprite": "chibi.png" }
}
```

把 JSON 拖入游戏的角色选择页，默认就有待机呼吸、行走起伏、跳跃拉伸、下落姿态、落地压缩、攻击前倾或后坐、闪避、受击和倒地动作。没有动画字段时使用 `animationMode: "auto"`，不需要填写动作曲线或状态机。

图片建议为**透明 PNG、完整人物、正面略朝右或侧面朝右、双脚在画面底部、左右留白相近**。尽量裁掉多余透明边缘。单张图默认按一帧处理，不会识别拼在一起的多个动作；图集需明确填写 columns/rows。默认显示高度 112，可用 `assets.height` 调整。

单图通过整体旋转、伸缩和位移提供反馈，不能凭空让图中的手脚独立运动。系统不会自动把任意插画拆成部件，也不会补画被身体遮住的手脚。需要真正迈腿、摆臂时使用下一种方式。

可直接导入 `examples/single_character.json` 体验。它自带一个用于观察默认动作的几何小人。

## 进阶：分件小人

建议拆成独立透明图：躯干、头、前后手臂、前后腿，可选武器。不必每个部件都齐全；有 torso 就可以组成一个分件角色，缺少的部件不绘制。武器必须有 armFront 作为父部件。

```json
{
  "id": "modular_hero",
  "name": "分件角色",
  "assets": {
    "parts": {
      "torso": { "image": "body.png" },
      "head": { "image": "head.png" },
      "armFront": { "image": "arm_front.png" },
      "armBack": { "image": "arm_back.png" },
      "legFront": { "image": "leg_front.png" },
      "legBack": { "image": "leg_back.png" },
      "weapon": { "image": "sword.png" }
    }
  },
  "attack": { "type": "melee", "amount": 2, "range": 120, "lifetime": 0.15 }
}
```

默认模式在发现 parts.torso 时使用分件绘制。`Front/Back` 表示绘制前后层，不是人体左右：朝向改变时整个骨架镜像，前后层顺序保持。

**素材要求：**手臂和腿在原图中向下伸直，关节处留少量重叠避免转动露缝；头部保留完整轮廓；武器默认图柄在下方约 85% 的位置、尖端朝上。部件会按配置高度缩放，保持原图宽高比；不同身体比例可覆盖关节点参数。这里是轻量的刚性部件动画，尚不包含肘、膝的多级骨骼、蒙皮或 IK。

### 默认关节和比例

所有身体部件的 x/y 均以角色双脚之间为原点，单位为角色总高度；x 向右，y 向下。pivotX/pivotY 为部件图片内的旋转中心，范围 0–1。

| 部件 | x | y | height / 角色总高 | pivotX | pivotY |
| --- | --- | --- | --- | --- | --- |
| torso | 0 | -0.65 | 0.38 | 0.5 | 0.1 |
| head | 0 | -0.67 | 0.36 | 0.5 | 0.9 |
| armFront | 0.18 | -0.61 | 0.33 | 0.5 | 0.1 |
| armBack | -0.18 | -0.61 | 0.33 | 0.5 | 0.1 |
| legFront | 0.09 | -0.31 | 0.34 | 0.5 | 0.1 |
| legBack | -0.09 | -0.31 | 0.34 | 0.5 | 0.1 |
| weapon | 0 | 0.85 | 0.40 | 0.5 | 0.85 |

**weapon 的 x/y 是例外：**以 armFront 的肩关节为原点，单位为前手臂高度，随前手臂旋转。默认 y=0.85 将握柄放在接近手的位置；weapon.height 仍是角色总高比例。

例如只修改头的位置和大小：

```json
"head": { "image": "head.png", "y": -0.70, "height": 0.40 }
```

分件会自动获得双腿交替、手臂反向摆动、空中收腿、上身攻击叠加、武器跟手等效果。近战普攻使用挥臂，弹道普攻使用抬臂后坐。行走时攻击保留腿部步态。通过平滑过渡减少状态切换时的突跳。

`examples/rig_character.json` 和同目录 `rig_parts/` 提供一套可直接导入的几何分件示例。先导入观察效果，再替换图片；通常只需少量调整 x/y、height 和 pivot。

## 已有图集如何兼容

`animationMode` 可选：

- `auto`：有分件时使用分件；否则，多格图集使用帧动画，单图使用程序动作。
- `rig`：使用分件，需要 torso。
- `frames`：使用配置的动作行；缺少动作行时叠加程序动作作为兜底。
- `procedural`：强制叠加程序动作；如果同时配置了图集，仍播放对应帧。

`idleRow` 默认 0。`runRow`、`attackRow`、`jumpRow`、`fallRow`、`dodgeRow`、`hurtRow`、`defeatedRow` 默认 -1，表示未提供，使用程序动作兜底。下落未提供 fallRow 时优先复用 jumpRow。行号从 0 开始，必须小于 rows。倒地帧播放一次后停在末帧。

每行可用 `rowFrameCounts` 指定有效帧范围，例如 `"rowFrameCounts": [7, 8, 8, 4]` 表示前四行分别使用前 7、8、8、4 格；未列出的行默认使用全部 columns 格。加载时还会自动剔除完全透明的空白格，菜单和战斗共用同一帧表，旧配置无需重新导入也会生效。空动作行回退到待机行。只有完全透明格被自动剔除，白色但不透明的合法美术帧不会被过滤。

已配置的帧动作会直接播放，避免再次叠加大幅形变。`assets.motionStrength` 默认 1，可在 0–2 之间调整程序动作幅度；0 关闭程序形变，逐帧播放仍然生效。旧配置中显式写入的行号会继续保留，不会猜测其实际含义。

## 代码与保存

- `CharacterAnimator`：每个角色自己的动作计时、步态相位、优先级和平滑姿态。死亡、受击、闪避优先于基础移动；攻击可叠加在空中或移动上。
- `Player`：传入真实速度、离地/落地、闪避、受击事件。普攻真正发出或技能成功施放时触发动作；按键处于冷却期间不会重复触发。
- `CharacterArt`：应用整体姿态、部件关节、层级与镜像，武器跟随前手臂。纹理仍在主线程创建和释放。
- `CharacterAssets`：动作选择、图集行、部件比例和资源引用都能进行 JSON 往返保存。
- 本地导入会复制全部分件图片；云端适配器会上传分件并将引用替换为 URL。网络层仍需要后续接入。

动作不修改角色物理位置、碰撞盒、跳跃速度、普攻间隔或伤害，视觉和战斗规则保持分离。当前新增默认动作作用于配置角色；原有能天使、德克萨斯的专属路径继续保留。

## 验证与预览

`character_tests` 覆盖状态优先级、空中攻击、落地事件、倒地不循环、独立动作实例、攻击触发时机、参数校验、分件本地导入与云端序列化。

运行 `character_render_smoke` 会在可执行文件旁的 `character-qa/` 生成 `default-actions.png`（单图与分件的同组动作）以及 `mirrored-actions.png`（朝左关节表现），同时生成单图与分件测试资源。素材中的几何形状仅用于检查默认动作，并非游戏角色美术成品。
