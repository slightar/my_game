# 保持原有表现的性能优化

本次只减少资源加载、字体查找和程序执行的重复开销。帧率仍为 60，分辨率、四倍抗锯齿、纹理过滤、粒子数量、动画速度、技能时序、碰撞和伤害计算均保持原样；霜星冰坑仍为第一条生命 4 HP、复活后 8 HP。

## 改动

- `UiFont` 加载字体时建立 Unicode 字形索引。单行绘制和宽度测量不再逐字扫描整个中文字体表；绘制矩形、间距、缺字回退与 raylib 5.5 相同。多行绘制继续使用 raylib，以保留全局行距设置。
- `Game` 等到收集完导入角色和战斗文本后再生成字体图集，避免启动时生成两次。后续刷新如果字形集合没有变化，也不会重新生成图集；新增自定义文字仍可正常加载。
- 两个 Boss 渲染器共享不可变的客户端特效纹理和动画数据，最后一个持有者释放时再卸载。弱引用缓存不会延长 GPU 资源的生命周期，下次创建渲染器时可以重新加载。
- UI 和特效资源表采用透明比较器，查询固定资源名称时避免构造临时字符串。
- 默认启用 `GAME_OPTIMIZE_DEBUG_BUILD`，为游戏及其运行库的 Debug 配置添加 `-O2`，仍保留调试符号和断言，不启用快速浮点计算。Release 的配置不变。需要逐行查看未优化的局部变量时，可设置 `-DGAME_OPTIMIZE_DEBUG_BUILD=OFF`。

## 验证和复测

`performance_audit` 使用隐藏窗口、四倍抗锯齿和 60 帧节奏，测量游戏对象初始化，以及主页、地图和四个 Boss 每帧更新与绘制提交的耗时。每个场景预热 20 帧、采样 120 帧，输出中位数与 P95；计时不包含帧率限制的等待，也不是 GPU 硬件计时。不同机器、驱动和后台任务会影响数值。

```powershell
cmake --build cmake-build-debug --target my_game performance_audit
./cmake-build-debug/performance_audit.exe ./output/performance --verify-font
ctest --test-dir cmake-build-debug --output-on-failure
```

需先构建 `my_game`，让原有构建流程复制资源到可执行文件旁边。审计程序不会重置游戏进度，也不会保存测试房间的状态。

`--verify-font` 将 192 组中文、英文、换行、空白、缺失字形、无效 UTF-8、不同字号和透明度的文本与 raylib 原绘制方式逐像素比较，同时检查测量宽度和字形支持判断；另检查相同字形集不会重新创建图集、新字形可加载、共享特效在一个渲染器销毁后仍然有效，以及最终释放和重新加载。

优化前后的完整场景截图也进行像素比较，主页、地图和四个 Boss 均保持一致。全部 16 项现有逻辑测试通过，包括 Boss 技能、角色动画时序和霜星冰坑生命值。

## 本机结果（2026-10-14）

以下为同一套资源、同一 Debug 配置、60 帧节奏下各运行三次的中位数。初始化不包含窗口和音频设备创建；帧耗时为更新及绘制提交。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 游戏资源初始化 | 4068.62 ms | 1755.14 ms |
| 主页每帧 | 0.9952 ms | 0.5491 ms |
| 地图每帧 | 1.2401 ms | 0.5604 ms |
| 弑君者测试房间每帧 | 2.0322 ms | 0.9655 ms |
| W 测试房间每帧 | 2.2279 ms | 1.1060 ms |
| 霜星测试房间每帧 | 2.2996 ms | 0.9890 ms |
| 爱国者测试房间每帧 | 2.0624 ms | 0.9856 ms |

初始化耗时减少约 57%，上述场景的帧处理开销减少约 45%～57%。共享特效省去 19,030,792 字节（约 18.1 MiB）的重复纹理分配，另避免重复解析动画数据。三轮共 18 对完整场景截图逐像素一致。风扇转速与温度没有作为本次测试指标。

原始测量日志、对照截图及 `summary.json` 保存在项目的 `output/performance` 目录。
