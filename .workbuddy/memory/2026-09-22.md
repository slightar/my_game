## 贴图透明度（差点误判成素材损坏）

Arknights 把颜色图与透明度存成两张，`enemy_XXXX_name[alpha]` 是遮罩，
**透明值在它的 R 通道**，不是 alpha 通道。正确合并：

```python
image = objects[model].image.convert('RGBA')
image.putalpha(objects[model + '[alpha]'].image.convert('RGB').getchannel('R'))
```

先写成 `.putalpha(alpha.getchannel('A'))`，结果 **0 个透明像素**（整图不透明），
但图能正常保存、尺寸也对，看起来像「作者没抠背景」。差点据此说素材有问题。
校验手段：`im.convert('RGBA').getchannel('A').histogram()[0]` 应为大数
（`enemy_1009_lurker` 实测 40145/65536 ≈ 61% 透明，106 个灰阶值）。

## 四、体型比例：改成从烘焙产物推导（用户抱怨的第三条）

烘焙器统一按 `scale = min(174/unionW, 164/unionH)`（spine 单位 → 像素）出图，
所以某模型的**真实尺寸 = (表中墨迹高度) / scale**，而这些 spine 单位在所有模型间通用。
把士兵（普通人类 367 单位）锚定 110px（玩家立绘 112px）→ `C = 0.29976 px/单位`：

- `height     = C × 单位高度`
- `spriteSize = C × 192 / scale`

`output/_tmp_new/size_table.py` 算出全表（重装防御者 392 单位 → 118px …… 源石虫
187.7 单位 → 56px），与 `enemy_data.cpp` **逐项核对一致**。上一版是手填 `spriteSize`，
猎狗被画成术师的一半大，尽管两个模型真实尺寸接近 —— 这就是用户看到的"比例失衡"。

两个容易踩的点：

- `spriteSize` 是**贴图方框边长**，不是可见高度。方框有透明留白，可见高度是 `height`。
- **`width` 不在这张表里**，它是手调的**受击盒**宽度。模型包围盒含张开的手臂和武器
  （士兵实测 398px 宽），照搬会让脚下阴影和格挡线宽得离谱。只有 `reach` / 阴影 /
  格挡线读它，与精灵绘制无关。`size_table.py` 打印的 `rig width` 是"不可用"的那列。

# 2026-09-22（第四次修订）德克萨斯「剑雨」按原作重做

用户要求「修改德克萨斯的剑雨，让其和游戏内一样」。

## 原作数据（已查证，两处来源一致）

德克萨斯 S2「剑雨」：**自动回复、手动触发**；立即获得 9~12 点部署费用；
对**周围所有敌人**造成**两次**相当于攻击力 **105%~170%** 的**法术伤害**，
并令击中目标**晕眩 2 秒**（专精后 3 秒）；初始技力 20~30，消耗 40。
范围是**自身周围 8 格**（3×3 区块）。**技能可对空**。

## 改前 vs 改后

改前（错的）：按 `SkillOne` 触发一段 **1.35 秒持续**的落剑雨，
剑从**敌人上方** ±130px 随机落下（`BulletKind::FallingSword`），
每把 1.55 伤害 + 0.42s 晕眩，冷却 14s。
问题：一次性瞬发被做成了持续雨、以敌人为中心而不是以德州为中心、晕眩过短。

改后：
- **瞬发、以德州为中心**的范围爆发，只按一次键。
- 每命中一次推一颗 `BulletKind::SwordRain`（新枚举），
  `radius = kSwordRainRadius(300)`，`DamageType::Arts`，
  `stunDuration = 2.0s`，**两次**靠 `activationDelay = 0.14s` 错开
  ⇒ 两个弹各画一圈脉冲，"两次法术伤害"**看得见**。
- 伤害 = `kTexasMeleeDamage(1.9) × 1.70 = 3.23` / 次（专三 170% 的比值翻译成本作单位），
  两次共 6.46。冷却 20s（原作 40 技力≈40s，这里为手感减半，已在注释里写明）。
- 施放时同时置 `texasAttackEffectTimer_ = kSwordRainBurstDuration` 以出招姿势。

## 关键实现点（改前必读）

- **`EnemySystem::ResolveBullet` 的 `melee` 已改名 `radial`**：
  `radial = (MeleeSlash || SwordRain)` ⇒ 圆碰撞、**一次可命中多目标**、
  **不受隐身过滤**（能打隐身弩手，因为它是贴身爆发不是飞行物）。
  非 radial 的仍是 `SegmentHit` + 命中即 `lifetime=0`。
  改动 `radial` 的定义前想清楚这两条差异。
- **`game.cpp` 不画 SwordRain**（`continue` 跳过），由 `Player::Draw` 统一画：
  只有那里同时知道 `swordRainTimer_`（剩余时间）和 `position_`。
  在 `game.cpp` 再画一遍会重影并且画在发射点。
- **`game.cpp` 的 boss 分支**：`if (kind != MeleeSlash && kind != SwordRain) lifetime = 0`
  ——范围技能不是"被消耗掉的子弹"，要保持存活到视觉时长结束。
- **`FallingSword` 不能删**：`character.cpp` 的 `EffectType::Rain`（模组角色的
  「剑雨」技能，见 `demo_guard.json`）还在用它。**它是另一套东西**，
  与德州内置技能无关，别混。
- **不要用 `texasRainBurstTimer_` 播施放动作**：它驱动 S2 战斗立绘的 `ending` 分支，
  帧号按 `0.18 - timer` 算，而爆发时长 0.46s 会让帧号为负 → 源矩形越界画出垃圾，
  并且会误播阵雨模式的"退出"叠层。用 `texasAttackEffectTimer_` 即可。
- 键位：`kDefaultKeys` 顺序为 `{A,D,W,S,J,R,KEY_Q,KEY_E,ONE,TWO,ESC}`，
  对应 `skillOne=Q`、`skillTwo=E`。所以 **E = 阵雨连绵（模式开关），Q = 剑雨**，
  与 HUD 两个图标的字母标签一致。

## 范围：用户选择「保持半径 300 的圆」

原作是 1.4 格左右的小范围（贴身），且打不到空中单位；本作 1 格≈112px（近战距离），
忠实半径只有约 170px。给了三个选项（椭圆 170/330、忠实圆 170、保持 300 圆），
**用户选择保持半径 300 的圆**——覆盖空中妖怪、手感更像大招，代价是比原作大。
这是有意为之的偏离，**不要再"顺手改成忠实的 170"**。
