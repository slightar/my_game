# 2026-09-25

## 关卡选择页第三次改版：交错阶梯折线 → 横向轨道 + 横向滚动

### 用户反馈

看完昨天的「交错阶梯折线」版，用户说：**「不是这样的，和游戏一样，是左右向的」**
——方向就是错的：关卡链条要**左右走向**，不是上下。

### 硬约束（这才是关键）

瓦片是 166×82（官方素材原尺寸，不能缩，缩了就不是像素级还原）：

```
5 × 166 = 830           关卡横排所需宽度
        + 371           详情面板 details_bg 宽度
        = 1201  >  1024 画布宽
```

**关卡和面板没法同时平铺。** 而且游戏里第一章有 **12 关**（1-1 … 1-12），
本来就不可能一屏放下 —— 所以一定是横向滚动。

把这两个方案画给用户选，用户选了 **B：关卡横排在左、可横向滚动 + 详情面板常驻右侧**。

### 新布局（B 方案）

- **章节改为顶部标签条**：`#tabs` left 25 / top 20 / width 975，5 个 flex 等分标签，
  选中态橙色下边框。原来左侧那一列章节列表占掉 200px 宽，横排后必须让出来。
- **关卡轨道**：视口 `#rail` left 25 / top 224 / **585×192**，`overflow:hidden`；
  内容 `#rail-inner` 宽 **1054**，用 `translateX(-scroll)` 平移。
  - 瓦片 166×82，水平步进 **PITCH = 222**（间隙 56）
  - **上下交错 80px**：偶数关 `top=10`、奇数关 `top=90`（视口内坐标）
    → 折线才有竖向段可折，不是一条平线
  - 折线用**橙色 `line_spst`**：出/入横段各 `GAP/2 = 28`px，竖段 4×80
- **节点标记**落在折线的竖直转角上：x = `i===0 ? 194 : 222i-28`（= 上一段折线的拐点），
  y = 关卡中线。当前=39px 橙菱形、已通关=23px 橙圆点、未解锁=23px 灰点。
- **横向滚动条**：包里的 `scrollbar`（7×25，不透明白 255,255,255）+
  `scrollbar_bg`（7×25，半透明白 alpha 77）**旋转 90°** 当横向滚动条用。
  拇指宽 = 585×585/1054 ≈ **325**，行程 = 585-325 = **260**。
- 滚动范围 `MAX_SC = 1054-585 = 469`。交互：**滚轮**（rail 上 wheel 事件）、
  **拖动拇指**、**点击轨道跳转**，另外选中关卡后 `revealStage()` 自动把它滚进视野。
- 详情面板 `left=629 top=74`，371×478，不变。

### 验证

`verify_page.js` 加了**滚动相关断言**（这是新版最容易出错的部分）：

- 点最后一块瓦片 → 必须滚到 `MAX_SC`（469）
- 滚轮 +300 → 300；+99999 → 钳到 469 且拇指 left=260；-99999 → 钳到 0 且 left=0
- 切章后**选中关卡必须在视野内**（不变量，而不是"归零"——切章会自动滚到选中关）
- 三段折线的坐标逐条核对（出横段 / 竖段 / 入横段）
- 23 个 data-uri、0 损坏 → **all geometry checks passed**

⚠ 第一次跑挂了两条，都是我**断言写错**不是代码错：① 滚轮测试前没把 scroll 归零；
② 断言"切章回到 0"，但切章后 `si = min(cleared,4)`，对全通的序章是第 5 关 →
`revealStage(4)` 会滚到 469。改成校验"选中关在视野内"这个真正不变量。

### 素材观察补充

- `scrollbar` 是不透明纯白（255,255,255,255），`scrollbar_bg` 是半透明白（alpha 77），
  都是 7×25 圆角长条 → **竖排列表的滚动条**。横向用就旋转 90°。
- 这反过来印证：包里确实存在滚动条，说明关卡列表**本来就是可滚动的**。
